# 🔎 Job Parser — QA-вакансии в Telegram

Каждые 3 часа GitHub Actions собирает свежие удалённые QA-вакансии с **Хабр Карьеры**, **hh.ru** и **Telegram-каналов**, DeepSeek оценивает каждую под резюме (0–10). Подходящие приходят в Telegram, а все оценённые складываются в **дашборд** на GitHub Pages, где ведётся воронка откликов.

```
GitHub Actions (cron) → main.py → Хабр + hh + TG-каналы
                                → предфильтр (ключевые слова, зарплата, свежесть, дубли)
                                → DeepSeek: оценка под resume.md
                                → Telegram-бот: только score ≥ min_score
                                → docs/vacancies.json → дашборд на GitHub Pages
                                → seen.json + vacancies.json коммитятся обратно в репо
```

## Структура

| Файл | Что это |
|---|---|
| `main.py` | Весь парсер: источники, фильтр, DeepSeek, отправка |
| `config.yaml` | Настройки: зарплата, порог оценки, каналы, ключевые слова |
| `resume.md` | Профиль для DeepSeek. **В репо не попадает** (в `.gitignore`), его текст хранится в секрете `RESUME_TEXT` |
| `docs/index.html` | Дашборд |
| `docs/vacancies.json` | Данные дашборда (обновляются автоматически) |
| `seen.json` | Память «уже видел» (обновляется автоматически) |
| `.github/workflows/parse.yml` | Расписание запуска |

## Запуск за 5 шагов

### 1. Telegram-бот
1. Напиши [@BotFather](https://t.me/BotFather) → `/newbot` → придумай имя → получишь **токен** вида `123456:ABC...`.
2. Открой своего бота и нажми **Start** (без этого бот не сможет тебе писать).
3. Узнай свой **chat_id**: открой в браузере `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найди `"chat":{"id": 123456789`. Это число и есть chat_id.

### 2. Публичный репозиторий на GitHub
Создай новый репозиторий, например `job-parser`, и выбери **Public**. Бесплатный GitHub Pages работает только для публичных репо, а Actions в них без лимита минут. Резюме в репо не попадёт: файл `resume.md` в `.gitignore`, а текст уходит в секрет.

Залей файлы через терминал из папки проекта:
```bash
git init                      # превращаем папку в git-репозиторий
git add .                     # кладём все файлы в «корзину» для коммита
git commit -m "first commit"  # фиксируем снимок файлов
git branch -M main            # называем основную ветку main
git remote add origin https://github.com/<твой-логин>/job-parser.git   # говорим, куда пушить
git push -u origin main       # отправляем на GitHub
```
> Можно и без терминала: на странице репо **Add file → Upload files** и перетащить всё. Папку `.github` при этом проверь отдельно: она скрытая и иногда не загружается.

### 3. Секреты
Репозиторий → **Settings → Secrets and variables → Actions → New repository secret**. Создай четыре секрета (секреты не видны никому, даже в публичном репо):

| Name | Значение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен от BotFather |
| `TELEGRAM_CHAT_ID` | твой chat_id |
| `DEEPSEEK_API_KEY` | ключ DeepSeek |
| `RESUME_TEXT` | весь текст из `resume.md` (скопируй и вставь) |

### 4. Включить дашборд
**Settings → Pages → Build and deployment**: Source — **Deploy from a branch**, Branch — **main**, папка **/docs** → Save. Через минуту там появится ссылка вида `https://<логин>.github.io/job-parser/`. Добавь её в закладки или на главный экран телефона.

### 5. Первый запуск
**Actions → Парсер вакансий → Run workflow**. Через 1–2 минуты в Telegram придут вакансии за последние 48 часов, а через пару минут после этого они появятся в дашборде. Дальше всё работает само каждые 3 часа.

## Дашборд
- Вкладки **Новые / В работе / Архив / Все**, поиск, фильтр по оценке и источнику, сортировка.
- У каждой вакансии статус (🆕 Новая → 📨 Откликнулся → 🗣 Собес → 🎉 Оффер / ❌ Отказ / 🙈 Не интересно) и поле для заметки («HR Аня, созвон в чт»).
- В дашборд попадают **все** оценённые вакансии, даже с низкой оценкой: так видно, что отсеивается, и удобно подкручивать `min_score`. По умолчанию показ с оценки 6+.
- Статусы и заметки хранятся **в браузере**. На другом устройстве их не будет, а при очистке данных сайта они пропадут — периодически жми **⬇️ Бэкап статусов**, а на новом устройстве **⬆️ Восстановить**.

## Настройка (`config.yaml`)
- `min_score` — порог оценки. Если приходит много мусора, подними до 7; если мало, опусти до 5.
- `min_salary_rub` — нижняя граница зарплаты.
- `channels` — список TG-каналов, добавляй любые публичные (имя без `@`).
- `include_keywords` / `exclude_keywords` — бесплатный фильтр до DeepSeek.
- `deepseek.model` — имя модели. Если DeepSeek её переименует, правится только эта строка.

Поменял резюме → обнови секрет `RESUME_TEXT`. Поменял конфиг → `git add config.yaml` → `git commit -m "порог 7"` → `git push`. Со следующего запуска работает новая версия.

> ⚠️ Перед `git push` сделай `git pull`: бот сам коммитит `seen.json` после каждого запуска, и без `pull` GitHub не примет твой пуш («ваша ветка отстала»).

## Локальный тест
```bash
pip install -r requirements.txt
python main.py        # без токенов: выводит вакансии в консоль, в Telegram не шлёт
```

## Что важно знать
- **hh.ru**: официальный API поиска вакансий закрыт для неавторизованных запросов с 2026 года, поэтому hh парсится через страницу поиска сайта. Это неофициальный способ: если hh поменяет вёрстку или покажет капчу, в логах Actions будет `hh: ошибка`, а остальные источники продолжат работать.
- **Стоимость**: GitHub Actions и Pages в публичном репо бесплатны. DeepSeek обходится в центы в месяц.
- **Публичность**: страница дашборда и список вакансий видны всем, у кого есть ссылка. Резюме, ключи и статусы откликов наружу не попадают.
- **Расписание** в UTC; GitHub иногда запускает cron с задержкой 5–30 минут — это нормально.
- Если вакансий слишком много, лишнее не теряется: сверх `max_messages_per_run` придёт в следующий запуск.
